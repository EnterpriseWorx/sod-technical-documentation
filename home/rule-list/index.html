Rule List

The Rule List is where you browse SoD processes and maintain the rules that detect SoD violations.

Permission: RuleView to open the list. RuleUpdate to add or edit a rule.

Open the process list

  • Navigate to Home >> Rule List.
  • The Process List shows every process in the ruleset.
Column Description
Key Process business key
Description Process name
Rule Count Number of rules in the process
  • Click View on a process to open its rule list.

Review rules in a process

The rule list title is {process key} Rule List. Use the back control to return to the process list.

Column Description
ID Rule ID within the process
Risk Rating High, Medium, or Critical Access
Rule Access Risk Description of the access risk
Transaction A Transaction on side A of the rule
Transaction B Transaction on side B of the rule
Approver Role Role that must approve operator mitigations for this rule, or No approver

You can search, filter, sort, and export this list.

Add a rule

  • Open the rule list for the process.
  • Click Add.
  • Complete the New/Update Rule form (see Rule fields).
  • Click Save. A Rule updated message confirms the change.

Note

New rules default to risk rating Medium. The process field is set for you and cannot be changed. Rule ID plus process must be unique.

Edit a rule

  • Click Edit on the rule.
  • Update the fields.
  • Click Save.

Rule fields

Field Notes
Process Read-only. Shown as description and business key.
Rule ID Up to 10 characters. Suffix after the process key.
Risk Rating High, Medium, or Critical Access.
Probability 1 through 5.
Source Type Syspro or FlowCentric (not implemented yet).
SAP Rule ID Optional external identifier (up to 100 characters).
Access Risk Description of the risk.
Transaction A Side A transaction (up to 100 characters).
Transaction B Side B transaction (up to 100 characters).
Program A Syspro programs on side A. All selected programs must be granted.
Program B Syspro programs on side B.
Activities A Syspro activities on side A. All selected activities must be granted.
Activities B Syspro activities on side B.
Approver Role Role that approves operator mitigations for this rule. Only roles with the RuleMitigationApprove permission appear. Choose No approver if mitigations should apply immediately.

A rule defines an SoD violation between side A and side B. A side can use programs, activities, or both. You can also define a one-sided rule by filling in only side A or only side B.

Note

When Approver Role is set, operator mitigations for that rule wait for approval. See The Rule Violation Mitigation Approval Process.

Note

FlowCentric appears as a source type on the form, but it is not implemented yet.
